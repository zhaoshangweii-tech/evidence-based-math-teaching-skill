# Deliverable and Quality Standard

## Produce an all-in-one delivery

Match the bundle to the task. A complete teaching-research delivery may contain:

1. Editable presentation or report.
2. PDF preview.
3. Page-by-page speaking notes or a verbatim script.
4. Student-response coding detail.
5. Source-page index and original-page folder.
6. Validation record.
7. Generator source when code produced the artifact.

Do not create extra files that have no review or reuse value.

## Presentation standard

- Follow the reference deck when one is supplied.
- Keep all explanatory text, diagrams, charts, and annotations editable.
- Use student images only for authentic handwriting or source evidence.
- De-identify student images.
- Keep one main claim per slide.
- Use counts and denominators near charts.
- Label observations separately from interpretations.
- Put detailed speaking language in slide notes.
- Render and inspect every slide at desktop resolution.
- Check long Chinese text, table density, image legibility, and font substitution.

## Script standard

A teaching presentation script should:

- follow the actual page order,
- include natural page transitions,
- state conclusions before details,
- explain why evidence matters,
- distinguish spoken text from stage directions,
- connect curriculum, textbook, student evidence, objectives, and activities,
- fit a declared speaking duration.

Do not narrate every visible element. Explain the instructional argument.

## Data standard

- Use a machine-readable detail file when coding many responses.
- Keep stable sample IDs.
- Include the rubric and ambiguity rules.
- Recompute summary values from the detail table.
- State whether categories are exclusive or overlapping.

## Review workflow

Use three stages when the user expects formal publication:

1. **Personal preview** — verify evidence, wording, and file completeness.
2. **Test-group review** — collect corrections on data, interpretation, and presentation.
3. **Formal release** — publish only the approved version.

Keep version names explicit. Do not overwrite the last approved delivery during major revisions.

## Final checklist

### Evidence

- Official-source scope is explicit.
- Edition labels are accurate.
- Key conclusions have page or sample references.
- Facts, interpretations, and hypotheses are distinguishable.

### Pedagogy

- Objectives derive from evidence.
- Each activity addresses a diagnosed obstacle.
- Questions advance student thinking.
- The teaching boundary matches the grade.
- Assessment evidence is observable.

### Artifact

- Requested file types exist.
- Files open successfully.
- Content is editable where promised.
- Slides or pages have no overflow or incoherent overlap.
- Images are legible and privacy-safe.
- Notes and scripts match the current version.

### Delivery

- Use a clear folder name.
- Include an index when many files are delivered.
- Provide the absolute path.
- Provide clickable links.
- Summarize the main conclusion and validation status.
